# Integer node implementation

Portable C99 code for the decision rules of the paper (integers only: no floating point, no 128-bit arithmetic),
the test vectors that fix their output bit by bit, the band-level score used for the vessel data, and the RIOT
application that was run on the Cortex-M3 and Cortex-M0+ boards.

## Files

| path | content |
|---|---|
| `alg/pam_common.h` | Fixed-point types (probabilities `p16` in units of 2^-16; price and token state in Q.32), price level rounding, xorshift32, CRC-32. |
| `alg/excl_node.[ch]` | Closed-loop rule with EXCL draws: block bookkeeping, one random word per block, comparator on the running accumulator; block starts supplied by the caller (`excl_step`) or computed online from the bin and the recording-start flag (`excl_forced_online`). |
| `alg/indep_node.[ch]` | Closed-loop rule with independent draws and per-unit price and token update (comparator `top16(xorshift32) < p16`). |
| `alg/extp_node.[ch]` | Open-loop probability unit shared by Robust Sampling and Active Measurement (they differ only in the 20-entry weight table): 20-entry look-up, 64-bit running sum of past weights, one unsigned 64-bit division. |
| `alg/madow_node.[ch]` | Single start per recording: one xorshift32 word at the first unit of a recording, running sum of `p16`, selection when the sum crosses an integer threshold. |
| `alg/baselines.[ch]` | Duty cycle and trigger (top-score) decisions. |
| `alg/bitexact.h` | Driver that runs the closed-loop family over the stored vectors and compares with the expected outputs. |
| `vectors/vectors.h` | 4096 consecutive score bins and recording-start flags taken from one whale-call development recording (bin indices only, no audio), two configurations, and the expected outputs (number of uploads, CRC-32 of the upload mask, final price level, final token state, number of blocks) of the Python fixed-point reference. |
| `vectors/vectors_madow.h` | Weight tables, constants and expected outputs for the open-loop single-start rule (four configurations: Robust Sampling and Active Measurement at b = 0.05 and 0.10; eight start seeds each). |
| `tests/test_native_madow_main.c` | Native test: 34 vectors of the closed-loop family, 32 vectors of the single-start rule, 4 self-checks. |
| `tools/check_madow_vectors.py` | Recomputes the 32 single-start vectors from the stored tables with exact Python integers (Python 3 only). |
| `score/` | Integer band-level score: 25--500 Hz band-pass at 2 kHz (two Q28 biquads), sum of squares per unit, log2 by look-up table, causal baseline, binning into 20 bins (`score.c`, `score.h`); `tables.h` (generated by `gen_tables.py`) holds the coefficients and a synthetic audio table, which is only used to time the code. |
| `riot_app/` | The application (`main.c`, `Makefile`) that runs the bit-exactness check at boot and times the decisions on the boards: cycle counter DWT on the Cortex-M3, SysTick on the Cortex-M0+. |

## Build and test on a computer

```
make test            # builds build/test_native_madow with CC (default cc) and runs it
python3 tools/check_madow_vectors.py
```

Without `make`:

```
mkdir -p build
cc -std=c99 -O2 -Wall -Wextra -Ialg -Ivectors -o build/test_native_madow alg/*.c tests/test_native_madow_main.c
./build/test_native_madow | tail -n 6
```

The last line must be

```
PASS: 66/66 vectors bit-exact (34 EXCL-family + 32 Madow), selfchecks 4/4
```

Every vector compares the number of uploads, the CRC-32 of the upload mask and the final state with the outputs of the
Python fixed-point reference without tolerance (the token state may differ by 2^-20 tokens, which is the rounding of the
floating-point reference). The test was run with clang (through `zig cc`) with `-std=c99 -O2 -Wall -Wextra` without warnings, and also with `-O0 -fsanitize=undefined` without reports. `sh test.sh` does the same as `make test` on systems without `make`.

`make score-check` compiles the score (compile check only).

## Boards

`riot_app/Makefile` builds the benchmark with RIOT (`make RIOTBASE=<RIOT directory> BOARD=iotlab-m3` or
`BOARD=samr21-xpro`). It first prints `BITEXACT SUMMARY PASS` and `BITEXACT_MADOW SUMMARY PASS (32 vectors)` if the board
reproduces all vectors, then times blocks of 1024 decisions for the closed-loop rule with EXCL draws, the open-loop
probability unit, and the probability unit followed by the single-start step.

## Test vectors

The vectors were produced by a Python fixed-point reference from one stream of score bins (4096 units of a whale-call development recording; bin indices only). The generator reads the development data and is therefore not included; `tools/check_madow_vectors.py` recomputes the single-start vectors independently with exact Python integers from the tables stored in the headers.

## Seeding

The generators are xorshift32 sequences: seed each node with a well-mixed non-zero 32-bit value (for example a hashed
device identifier). Small consecutive integer seeds give strongly correlated first outputs.
